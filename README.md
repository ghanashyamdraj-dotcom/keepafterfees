# AfterFees

Free calculators that tell online sellers and freelancers what they actually keep after
platform fees, payment processing, and tax.

Static site. No backend, no database, no runtime API calls. Every calculation runs in the
browser and works offline after first load.

---

## Quick start

```bash
npm run check
```

That runs the whole pipeline: validate rate provenance → build → test → audit against the
build spec. No dependencies to install; the project has zero npm packages by design.

Individual steps:

```bash
npm run build          # generate dist/
npm test               # 54 engine + parity tests
npm run audit          # score dist/ against the build spec rubric
npm run verify:rates   # validate rate data, regenerate VERIFY.md
npm run serve          # preview dist/ at http://localhost:4321
```

## Architecture

```
src/
  data/                  Rate + tax JSON. The only place numbers live.
    fees/                amazon, etsy, ebay, shopify, processors, resellers
    tax/tax-2026.json    Federal brackets, FICA, SE tax, QBI, retirement limits
    tax/states/          CA, NY, IL, TX, FL
    site.json            Org identity, nav, ad + affiliate config
  lib/
    money.js             Integer-cent arithmetic. Nothing computes in float dollars.
    result.js            The one result shape every calculator returns.
    calc/                One module per calculator. Pure, no DOM, no Node builtins.
    rates.generated.js   Built from src/data/. Gitignored.
  templates/             HTML generation: layout, components, JSON-LD
  client/                registry.js + app.js — the only script that ships
  content/
    tools.js             Master tool registry: nav, sitemap, internal links
    pages/               One file per tool page: fields, answer block, prose, FAQs
    legal.js             about / contact / privacy / terms / disclaimer
build/
  gen-rates.mjs          JSON → one ES module both Node and the browser import
  verify-rates.mjs       Fails the build on rate data with no source or date
  build.mjs              The static site generator
  audit.mjs              Scores dist/ against the build spec rubric
```

### Two decisions worth knowing

**Engines take rates as an argument.** `calculateAmazonFBA(input, rates.amazon)` rather
than importing data directly. That keeps every calc module pure and dependency-free, so
the same file is unit-tested in Node and served verbatim to the browser. A test that
passes is testing the exact numbers a visitor gets.

**Every calculator returns the same shape.** `{ ok, lines[], totals, warnings[], notes[],
meta }`. The result card, the copy button, the CSV export, and the print view are written
once and work for any calculator. Adding a tool is: write the engine, add one registry
entry, write the page.

## Adding a tool

1. The engine already exists in `src/lib/calc/` for all 15 tools.
2. Add a case to `buildEngineContext()` in `build/build.mjs` so the build can run the
   engine at the page defaults.
3. Write `src/content/pages/<id>.js` — copy `amazon-fba.js` as the template.
4. Flip `status: 'planned'` to `'live'` in `src/content/tools.js`.
5. `npm run check`.

The page file needs: `defaults`, `groups()`, `answerBlock()`, `content()`, and `faqs`.
The spec's 600–1,000 word minimum is enforced by `npm run audit`.

## Before you launch

These are blocking, in order.

**1. Verify every rate.** `VERIFY.md` is generated by the build and lists all 12 data
files with their primary sources. Nothing in `src/data/` has been confirmed against a live
source — the figures were seeded from published rate cards. Until `verifiedOn` is set, every
tool page displays a visible "not yet verified" banner, which is intentional. The highest-risk
entries are called out at the bottom of `VERIFY.md`; Mercari's seller fee is the least
certain number in the dataset.

**2. Fill in `src/data/site.json`.** Every field containing `REPLACE` — author name, bio,
job title, contact email. The build warns on each one. `Person` schema is suppressed
entirely while the name is a placeholder, and `npm run audit` fails on it. For a
money-adjacent tool site this is not cosmetic: an anonymous site is screened out of the
surfaces you are building for.

**3. Add `sameAs` URLs** that actually resolve. An empty array is correct until you have
profiles; a broken link is worse than an omission.

**4. Name a jurisdiction** in `/terms/` (marked TODO).

**5. After deploying, verify the CDN is not blocking AI crawlers.** Cloudflare has shipped
defaults that block them on new domains, so `robots.txt` can say Allow while the edge
returns 403. From outside your network:

```bash
curl -A "OAI-SearchBot" https://keepafterfees.com/amazon-fba-calculator/ | grep "dimensional weight"
```

If that returns nothing, the page does not exist as far as ChatGPT, Perplexity, or Claude
are concerned.

**6. Set up Bing Webmaster Tools**, not just Search Console. It is free, takes ten minutes,
and is the index behind ChatGPT search.

**7. Do not apply to AdSense** until 15–25 substantive pages are live with some history.
Ad slots render as reserved empty space right now, so enabling them later causes zero
layout shift.

## Deploy

```bash
npm run build
npx wrangler pages deploy dist --project-name afterfees
```

Cloudflare Pages, free tier, commercial use permitted. `dist/_headers` sets caching and
security headers. `dist/404.html` is picked up automatically.

## Annual maintenance

The tax layer is the moat and it decays every year.

1. Copy `src/data/tax/tax-2026.json` to the new year and update from the IRS revenue
   procedure (published each autumn) and the SSA wage base announcement (each October).
2. Update each file in `src/data/tax/states/`.
3. Bump `taxYear` in `src/data/site.json`.
4. `npm run check`.
5. Set `verifiedOn` on each file you checked. Page copy, titles, and the visible
   "last reviewed" date all follow from that field.

Fee schedules change more often than annually and with less warning. Amazon revises the FBA
rate card at least yearly; resale platforms have moved commissions between buyers and
sellers twice since 2024.
